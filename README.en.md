# Wincer's Blog

Personal blog built with Astro Content Layer + SolidJS islands. This migration lives on `codex/astro-solid-experiment`. The legacy Hugo + SolidStart implementation is preserved in `legacy/hugo-solidstart`.

## Features

- Astro static pages with ClientRouter navigation
- Astro Content Collections pipeline (`_blogs/content` → custom loader → sanitized content)
- Multi-language pages and posts
- RSS/Atom, sitemap, and public assets emitted at build time
- Optional encrypted posts (encrypted in build output)
- Service worker update notification

## Tech Stack

- Astro + SolidJS islands
- Astro Content Layer (validation, loading and development updates)
- Vite + UnoCSS
- Typesafe i18n

## Project Structure

- `src/astro/pages/` routes (content pages under `src/astro/pages`)
- `src/features/pages/` page view components
- `src/astro/layouts/` layout shells
- `src/features/` cross-cutting features (e.g. `features/theme`)
- `tools/content/` content pipeline utilities
- `_blogs/content/` markdown source (external content repo)
- `src/astro/content.config.ts` collection definitions (only sanitized fields are persisted)

## Content Workflow

1. Write content in `_blogs/content/posts` and `_blogs/content/pages`.
2. The Astro loader validates frontmatter and renders Markdown with the official Unified processor and existing plugins.
3. Existing Atom, sitemap, search and encryption generators write assets into `.astro-public`; OG images are generated by a separate Astro endpoint.
4. Pages consume sanitized entries through `astro:content`; browsers hydrate only interactive islands.

Development watches additions, edits and deletions, refreshing routes, taxonomy and generated assets. Rendered source is cached only in process memory; plaintext and passwords are never persisted in the Content Layer.

### Encrypted Posts

If a post has `encrypt_pwd` in its front matter, the build will:

- Encrypt the HTML and store it in the Content Layer entry under `html`.
- Remove the original `encrypt_pwd` from the output.
- Add `encrypted: true` so the UI can prompt for a password.

### OG images

`src/astro/pages/og/[image].png.ts` emits the existing `/og/*.png` URLs during production builds and renders on demand during development. It retains Satori layout and resvg rasterization, with asynchronous lossless PNG encoding through Sharp to avoid compressing each image on the JS thread.

Complete PNGs are cached in `.cache/og/`, with checksums and invalidation for displayed content, template, fonts, renderer dependencies and dimensions. `bun run clean` preserves this cache; `bun run clean:og` removes it. CI must persist and restore `.cache/og/` to reuse it across deployments. It is not a deployment artifact; retained cache entries do not create published routes.

## Development

```bash
bun install
bun run dev
```

Content build only:

```bash
bunx astro sync
```

## Build

```bash
NODE_ENV=production bun run build
```

Output is generated in `dist/astro`. This repo is intended to be deployed to Cloudflare Pages.

## Optional Build Script

`build.sh` is a convenience script that:

- Installs deps
- Pulls `_blogs` content
- Builds content and site

If your content repo is private, set `GH_TOKEN` for the clone step.

## Environment Variables

- `GH_TOKEN` (optional): used by `build.sh` to clone private content repo
- `CF_PAGES_BUILD_ID` / `CF_PAGES_COMMIT_SHA`: used to hash the service worker version

## Notes

- The content repo is separate from this codebase. Ensure `_blogs/` exists locally.
- `.astro` and `.astro-public` contain generated data; deploy only `dist/astro`.
